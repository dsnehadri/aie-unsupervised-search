Cutting the fabric's one-event latency
======================================
Block-level synthesis, object attention block, 12.8 ns clock (78.125 MHz)
unless stated. Baseline is the deployed build: integer layer norm (LN_MODE 5)
with OBJ_DATAFLOW.

  variant                                   latency  DSP   LUT      slack
  baseline                                    5762   183   32,979   +0.06
  SOFTMAX_PIPE                                3066   207   34,057   +0.06
  + HEADS_UNROLL                              3009   204   40,949   +0.14  (negative)
  + LN_MODE 6                                 2663   168  177,208   +0.10
  + LIN_FABRIC_MUL                            2660    72  238,552   +0.07
  same at 10.0 ns                             2687    72  238,554   +0.02

What each lever did, and why
----------------------------
SOFTMAX_PIPE (1.88x alone). The twelve row softmaxes ran one after another,
each a ~70 cycle serial chain, ~840 of the ~1200 cycles a head cost. One
PIPELINE pragma on the row loop overlaps them, for +24 DSP.

HEADS_UNROLL (2%, kept as a negative result). It did unroll: the loop is gone
and the sub-loops appear four times in the report. But each head's body is a
sequence of pipelined loops and HLS runs distinct loops back to back, so the
four copies executed in series, 1416 cycles = 4 x 354.

HEADS_BATCHED (heads stage 4841 -> 273). The head index becomes the
innermost unrolled dimension of each pipelined loop, so all four heads share
every iteration. No copies, unlike the earlier dataflow-per-head attempt.

LN_MODE 6 (layer norm 373 -> 27 cycles, FFN 2170 -> 786). Mode 2's
row-pipelined integer layer norm with the multiplies bound to LUT fabric.
Costs ~34k LUT per layer norm, which is why it cannot go everywhere: fourteen
of them plus fabric linears puts the design near 86% LUT. Mode 2 on DSP is
the same 15-cycle norm at ~38 DSP each; with the linears in fabric freeing
~660 DSP that fits, and is what the full design should use.

LIN_FABRIC_MUL. No latency change; DSP 168 -> 72. It pays for the rest.

100 MHz. HLS meets 10 ns with +0.02 ns at the block level, at +1% cycles. A
22% clock gain for the whole chain if the full design closes; the fabric
design closes 12.8 ns with +0.64 ns post-route today.

Remaining big items in the block (cycles): FFN 904, QKV 601, reshape 385,
project 196. The linears run at II=2 with 8-way partition; LIN_PARTITION=16
should halve them. Reshape is data movement and should be ~50.

Lever 5, one ABC layer
----------------------
retrain_tune.py, the deployed model's recipe (ISR 0.5, RAND 2.0, lr 1e-3,
150k background, best epoch by hi-mass AUC, 6 epochs), on the GPU:

Where neither collapses the two are equal to 0.002. Collapse (every jet to
one candidate, m_light = 0) is the known failure mode of this training and
is why the deployed run is named noncollapse; two of five two-layer seeds hit
it, none of the one-layer seeds so far. One layer removes obj1, cand2 and
cross1 from the one-event chain, about half of it.

The hardware path for one layer already exists: GAP_TEST_NOLAYER1 is
structurally the one-layer model (obj0 -> cand -> cross0 -> final jet choice
from cross0's output, as PyTorch with attn_blocks_n=1). It was "scores
meaningless" only because it ran two-layer weights. The exporter now emits
layer 0's weights in layer 1's slot when a checkpoint has none.

A correction found on the way
-----------------------------
The "software reference" used since 5 September scored 0.9688 with rank
correlation 0.89 against the hardware, and that gap was being read as the
cost of int16 quantisation. It was not. make_auc_eval_set.py zeroed the
embedding's input BatchNorm in torch without fusing it into the linear, which
is the model with its input normalisation removed. export_phase3.py fuses BN
into the linear correctly, so the hardware always computed the full model.
With BN active the true reference is 0.9818 and the rank correlation with the
fabric hardware is 0.9967: quantisation costs 0.0007 of AUC. Both reference
scripts are fixed and both .npz references regenerated; the broken one is
kept as auc_eval_ref_BROKEN_bn_neutralised.npz. The committed figure notes
already quoted 0.9818, so nothing in the paper carried the wrong number, but
the measurement printouts in this session did.

Second round: linears and reshape
---------------------------------
LIN_PARTITION=16 changed nothing because the linear already runs at II=1
over its 192 outputs (195 cycles). LIN_J_UNROLL=F computes F outputs per
cycle instead. RESHAPE_FAST rewrites the reshape helper as two pipelined row
passes (the original pipelined only the innermost 4-iteration loop and paid
fill on every head-row pair: 255 cycles for 25 rows); under HEADS_BATCHED the
object block writes its packed channel directly from the projections in one
13-row pass, skipping an intermediate copy (385 -> ~15).
Native sim with RESHAPE_FAST + LIN_J_UNROLL=4 on top of the build-A flags:
bit-identical to the deployed design, 2000/2000 events.

Third round: the multiplier width
---------------------------------
Every product site cast both operands to acc_t (32 bit) BEFORE multiplying,
so HLS built 32x32 multipliers for 16x16 products: 2 DSPs per MAC (the
"~1030-DSP floor" of the pairwise MLP is 576 MACs), and ~4x the LUTs once
the multiplies moved to fabric. NARROW_MUL multiplies at the operands' own
widths. The exact product is the same number and is rounded once at the
accumulate in both forms, and the native sim agrees: bit-identical on both
designs, 2000/2000.

  obj, full set                       583     197   476,349
  obj, full set + NARROW_MUL          597      97   287,459   -40% LUT
  cross, full set                     719     107   521,146
  cross, full set + NARROW_MUL        721      43   272,322   -48% LUT
  pairwise, II 16 as built           2746     321   103,713
  pairwise, PAIRWISE_FAST II 1        553       9   860,825   never shares
  pairwise, PAIRWISE_FAST + NARROW    553       9   390,476   -55% LUT
  (pairwise at II 2/4/8: same LUT as II 1, longer latency; a mul allocation
   cap does not make HLS share fabric-bound multipliers, so II 1 it is)

Projected one-layer chain, cycles at 100 MHz: fork 161, pairwise 553 (embed
in parallel), obj 597, cand ~350, cross 721, lorentz 759, AE 416, write 4:
~3560 = 36 us, plus the ~24 us host launch = ~60 us against 521 today.
The host launch is now 40% of it; lorentz and the AE are the last untouched
stages. Round-three builds: plstream_lat1L3 (one layer, everything, 100 MHz)
and plstream_lat78c (two layers, everything, 78 MHz).

Fourth round: the plumbing
--------------------------
With the compute cut, the stream transfers between stages were the largest
item left: every tensor moved one element per cycle, ~192 cycles for 12x16,
and a stage's read plus write (~700 cycles for an attention stage) exceeded
its compute (~600). WIDE_STREAMS packs eight 16-bit lanes into a 128-bit
word, so a 12x16 tensor is 24 words. The lanes carry the same bits and every
cast stays where it was, and the native sim agrees: bit-identical on both
designs, 2000/2000. LORENTZ_PIPE pipelines the three candidates' mass
sqrt/divide chains (same float ops per candidate, bit-identical).
Fourth-round builds: plstream_lat1L4 (one layer, everything, 100 MHz) and
plstream_lat78d (two layers, everything, 78 MHz).


MEASURED ON HARDWARE: the two-layer design (2026-09-12)
========================================================
The one-layer experiments are abandoned: one ABC layer is a different network,
so hardware numbers from it do not describe the model this paper ports. All of
the following keeps BOTH ABC layers and the deployed weights.

What killed the first attempt: LN_MODE 6 and LIN_FABRIC_MUL both trade DSP for
LUT, and were adopted when the LUT headroom was believed to be 1.55 M. It is
669 k -- the earlier reading took the REG column of the utilization report for
the LUT column. Two layers with those levers needs 1,109,602 LUT against
899,840 available, 123%, and the placer never runs.

Keeping the multiplies on DSP and narrowing them instead inverts the trade.
Object block, csynth, 12.8 ns:

  variant                                    latency   DSP      LUT
  baseline (deployed)                          5762    183    32,979
  NARROW_MUL only                              5834    110    28,218
  + SOFTMAX_PIPE                               3138    134    29,296
  + RESHAPE_FAST          <- built as t2a      2826    133    28,829
  + HEADS_BATCHED         <- built as t2b      2295    181    71,368

t2a is 2.04x on the block using FEWER DSP and FEWER LUT than the design it
replaces. t2b fails at implementation on DSP: head batching needs four times
