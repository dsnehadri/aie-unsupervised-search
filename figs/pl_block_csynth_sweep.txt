# Object attention block alone, vitis_hls 2025.2, xcvc1902, 12.5 ns (80 MHz), 2026-09-09.
# Sweep of the linear layers' k-partitioning (LIN_PARTITION): 8 = as built,
# 16 = the full row, which the header comment says was ruled out because the
# csynth DSP estimate reached 107% of the device.
#
#   LIN_PARTITION   block interval   DSP        LUT
#   8               9202 cycles      181 (9%)   42,789 (4%)
#   16              9202 cycles      181 (9%)   42,789 (4%)
#
# Identical: the linear layers are not the limit. Loop level:
#   LIN_I_LIN_J (one linear, 192 row-outputs)   193 cycles   -> already II=1
#   LN_ROW      (one layer norm, 12 rows)       660 cycles   -> 55 cycles/row
# The layer norm costs 3.4x the matrix multiply it follows. Budget of the 9202:
# ~7 linears = 1350 (15%), ~5 layer norms = 3300 (36%), softmax/context 751,
# the rest in skip-and-norm, reshape and concat.
#
# Same pathology as the AI Engine kernels before the integer rewrite: the fabric
# layer norm keeps its statistics in float32 (209 DSPFP32 slices in the routed
# design) and does a float sqrt and divide per row. An integer version would take
# the block to roughly 6200 cycles (~1.5x), i.e. PL-only near 135 us/event against
# 205 today -- narrowing, not closing, the gap to the hybrid's 58 us.
# NOT IMPLEMENTED: this is arithmetic on the report, not a measurement. The block
# also costs 16,269 cycles in the routed full design against 9202 here, so treat
# the standalone figure as a lower bound.
#
# LAYER-NORM SWEEP (same block, same clock, 2026-09-09). LN_MODE:
#   0  float32 statistics, row loop not pipelined (as built)
#   1  same arithmetic, row loop pipelined
#   2  integer statistics + rsqrt table, row pipelined
#   3  as 2 but row loop at II=4 (shares the element multipliers)
#   4  as 2 without the pipeline pragma
#   5  as 4 with the element loops unrolled by 4
#
#   mode   block cycles   DSP        LUT       LN_ROW
#   0      9202           181 (9%)   42,789    660
#   1      6172           316 (16%)  117,432    44
#   2      6027           334 (16%)  45,318     15
#   3      6222           298 (15%)  46,218     54
#   4      6027           334 (16%)  45,318     15   <- identical to 2
#   5      7762           178 (9%)   31,582    372
#
# Two findings. First, 4 matches 2 exactly, so the whole 660 -> 15 win is the
# integer arithmetic, not the pipelining; pipelining the float version (1) only
# reaches 44 and costs 2.7x the LUTs. Second, PIPELINE II=1 force-unrolls the
# inner loops whatever an UNROLL factor says, which is where the extra 153 DSP
# per block come from; without it, factor=4 shares them (mode 5).
#
# Mode 5 is free -- same DSP, 26% fewer LUTs, 1.19x on the block -- and is what
# the full design is built with. Modes 2/3 are 1.5x but need +117 to +153 DSP
# per block; with six attention blocks and 338 DSP spare on the device, they do
# not fit. On a larger part they would.
#
# Numerics: the integer path is within 1.01 LSB (max) and 0.34 LSB (mean) of the
# float path it replaces over 640k random rows -- src/attn_block_pl/layernorm_fixed_test.cpp.
#
# ON HARDWARE (full design rebuilt with LN_MODE=5, 2026-09-09):
#   PL-only, float layer norm  : 205.2 us/event, 4,872 ev/s, one event 901 us, AUC 0.9819
#   PL-only, integer layer norm: 128.4 us/event, 7,788 ev/s, one event 527 us, AUC 0.9825
#   1.60x, physics unchanged (rank correlation 0.9977 against the hybrid reference).
#   Fit at 93.4% DSP (1838, up from 1630 -- ~9 instances use layernorm, not one),
#   LUT 260,582 (down from 306,597), BRAM 100 (the table), timing closed at 80 MHz.
# The standalone block synthesis predicted only 1.19x: it sees one block with no
# memory contention, so treat a block-level estimate as a lower bound.
#
# NEGATIVE RESULT: pipelining the fabric attention block finer buys almost nothing
# (four hardware builds, 2026-09-09/10, all AUC 0.9825 -- no arithmetic changed).
#
#   build                                   longest stage (csynth)   measured interval
#   integer layer norm only                        --                 128.4 us
#   + object block split, 6 dataflow stages    8532 cyc = 107 us      131.1 us  (worse)
#   + stage wrappers made dataflow regions     7722 cyc =  96 us      124.1 us
#   + every inter-stage FIFO depth tripled     7722 cyc =  96 us      124.1 us  (no change)
#
# The measured interval sits ~25 us (~2000 cycles at 80 MHz) ABOVE the longest
# synthesized stage in every build, and that offset does not move: not when the block
# is split, not when the wrappers are restructured, not when every FIFO is tripled
# (which is what gave the hybrid 1.92x). So it is neither stage cost nor inter-stage
# backpressure. Most likely per-event dataflow synchronization that csynth does not
# model, but that is not proven.
# => the fabric baseline is limited by something outside the stages; quote 128.4 us
# (the simple build) and treat finer pipelining as a measured dead end. Contrast with
# the array side, where moving one stage off the fabric gave 3.35x.
#
# FABRIC MULTIPLIERS (BIND_OP impl=fabric on the linear layers), object block, 80 MHz:
#   variant            II      DSP        LUT
#   DSP  (as built)    5762    183 (9%)   32,979 (3%)
#   fabric             5762     87 (4%)   94,323 (10%)
# DSPs halve at IDENTICAL II -- the multiplies were never on the critical path, which
# matches the layer-norm finding. Across six attention blocks this frees ~580 DSP
# (design is DSP-bound at 93%), at ~370k more LUT (design uses 252k of 1.8M).
# That is what would make four-way head parallelism affordable: the block would go
# 6585 -> ~2288 cycles (3.4x) but needs ~4x the head multipliers.
# UNTESTED: fabric multipliers are slower in ns and the design closes 80 MHz with only
# +0.69 ns slack, so timing closure is the real risk; csynth does not show it.
#
# FOUR-WAY HEAD PARALLELISM: NEGATIVE. Object block, 80 MHz:
#   serial heads (as built)          II 5762   DSP 183 (9%)   LUT  32,979
#   4 heads as parallel processes    II 7850   DSP 311 (15%)  LUT  49,918
#   + fabric multipliers             II 7850   DSP 215 (10%)  LUT 111,262
# 36% SLOWER, not 2.5x faster as the stage arithmetic suggested. A dataflow channel
# may have one consumer, so each head process must copy its own Q/K/V out of a private
# array, and the split/merge stages needed to arrange that cost more than the
# concurrency saves. Fabric multipliers behave exactly as advertised (311 -> 215 DSP at
# identical II) but there is now nothing worth spending the freed DSP on.
# => the DSP budget was never the obstacle; the dataflow copy overhead is.
