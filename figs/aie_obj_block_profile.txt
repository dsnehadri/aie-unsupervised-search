# HARDWARE CONFIRMATION (blocks3 batch sweeps; final numbers are the 4 KB stack rebuild,
# which reproduced the 2 KB run within noise: object 17.7, candidate 3.9 vs 4.0, cross 17.1)
# isolated AIE block, us/event (events/s):   float LN            vector integer LN
#   Object attention                          54.6 (18,326)       17.7 (56,468)
#   Candidate attention                       13.3 (75,247)        4.0 (252,881)
#   Cross attention                           54.6 (18,328)       17.1 (58,462)
# end to end, AIE-PL hybrid with deep FIFOs:  57.9 us/event both ways -- the PL embedding
#   stage (59 us) now sets the rate -- but one event takes 392 us instead of 816 us.
# AUC on the 2000-event labelled set: 0.9818 both ways (rank correlation 0.9997).
# FIFO DEPTH x KERNEL, end-to-end interval of the cross-event pipelined hybrid (us/event):
#                        shallow FIFOs   deep FIFOs (all depths x3)
#   float layer norm        111.0            57.9
#   vector integer LN        57.9            57.9
# Both fixes remove the same bottleneck. Once the AI Engine stage is fast the extra
# buffering does nothing, and the floor is the PL embedding stage at 59 us.
# STACK. Deepest call path (main -> post kernel -> layernorm_row), from the profile reports:
#   float layer norm 416+1088+288 = 1792 B; 64-bit integer 416+992+160 = 1568 B;
#   vector integer   416+1184+384 = 1984 B, against the default 2048 B stack.
# With 64 B of headroom the 24-instance vehicle hangs the CU at 7 instances and above:
# past a core's stack lies a neighbour's buffer. Rebuilt with --stacksize=4096 it runs
# all 24 instances: 288 tiles give 51,959 events/s (was 43,772 with the float kernels).
# EMBEDDING KERNEL (aiesimulator profile of embed_mlp, one tile, 4 events, 2026-09-09):
#   20,993 cycles/event = 16.8 us. Layer norm 27%, the zero-init of the padded input 6%,
#   the three gemms almost free. Program memory 8,002 B, stack 1,664 B (4 KB stack).
# Moving the stage there makes the object attention block (17.7 us) the longest stage,
# so the projected interval is ~18 us (about 56,000 events/s), a 3.2x speed-up. Allowing
# the ~3 us of window handoff the attention blocks show between simulation and hardware,
# 18-21 us is the honest range until it is built and measured.
#
# EMBEDDING ON THE ARRAY, measured 2026-09-10 (after fixing the weight alignment):
#   interval 17.3 us/event (57,917 events/s) vs 57.9 us with embedding on the fabric -- 3.35x
#   one event 355 us (was 393); 2000 events 34.9 ms (was 116.2 ms)
#   AUC 0.9822 vs 0.9818, rank correlation 0.9984 -- no physics lost
# The kernel profile predicted 16.8 us/event and the built design measures 17.3, so the
# interval is set by the object attention block (17.7 us isolated), as the stage model said.
#
# LINK OVERHEAD alpha, fitted from sweep_v2_hw.csv (payload 1 KB - 1 MB, T = alpha + beta*B):
#   AIE window passthrough  DDR -> PL -> AIE -> PL -> DDR   alpha = 25.1 us
#   PL loopback control     DDR -> PL -> DDR, no AIE        alpha = 24.8 us   <- the control
#   no-DDR variant          PL -> AIE -> PL, on-chip buffers alpha = 14.4 us
# So alpha is launch + DDR: the array crossing adds 0.3 us on the intercepts (per-payload
# differences scatter -3.0 to +1.9 us, hence quoting ~1 us with a bound of ~2). The 10 us
# attributed to DDR is the OTHER subtraction, 24.8 - 14.4. Quote all three numbers so both
# subtractions are checkable; the control's alpha is what makes the crossing claim testable.

# into the gemm block layout with interleave_zip, the bias/residual adds are
# saturating vector adds, and the "= {0}" stack memsets are gone. The previous
# profile had the post kernels at ~80% scalar window copies (~18 cycles per
# int16) plus a 2,700-cycle byte-wise memset. x86sim outputs are bit-identical
# to the previous kernels (20 events x 6 blocks, and the embedding); on the
# hardware ISA (aiesimulator) the object block matches x86sim line for line.

# Head post 10.1 -> 5.0 us: the integer softmax ran 156 scalar exponentials
# (branch + LUT + variable shift) per event. Now per row: d = max - x in int32
# lanes, t = d*log2e/score_scale in 8-lane fp32, k = round(t), 2^-f by a
# degree-4 polynomial, times 2^-k by subtracting k from the exponent bits;
# row sums by vector reduce; ONE vector Newton reciprocal (bit-trick seed, 3
# steps) for all 12 rows instead of 12 scalar float divides (the divides were
# 21% of the kernel: 7.7 us with them, 5.0 without). Not bit-identical to the
# integer softmax: x86sim vs the PyTorch golden, obj max error 0.031 -> 0.034
# (L0), 0.007 -> 0.009 (L1); cand/cross untouched. aiesimulator == x86sim.
# Head post stack 2880 B (of 4096 with --stacksize=4096; main adds ~416).
# Object block critical path pre 2.0 + post 5.0 + a_proj 3.4 + b1 3.3 + b2 3.3
# + c 6.0 = 23 us (was 65 with the float-LN-fixed kernels). post_c (43% layer
# norm) is now the slowest kernel and sets the block interval.
