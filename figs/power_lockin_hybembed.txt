Power and temperature of the headline design, by lock-in
========================================================

Design: AIE-PL hybrid with the jet embedding on the AI Engine array.
17.3 us/event, 57,917 events/s, AUC 0.9822.
Method: 49 cycles of 120 s ON / 120 s OFF, 1 Hz sampling of the INA226 rails
and the on-die sensors. Each cycle's delta is the interior of the ON window
minus the interiors of the two flanking OFF windows, skipping 35 s after an
ON edge and 20 s after an OFF edge. Quoted error is the standard error over
the 49 cycles. The ON window is time-based, so it is 120 s on every design
regardless of how fast that design runs.

                            hybrid            hybrid + embedding
                        (embedding in PL)        on the array
  throughput              17,263 ev/s            57,917 ev/s
  total dP              437.6 +- 10.4 mW       961.0 +- 9.7 mW
    VCCINT              212.4 +- 10.2 mW       718.9 +- 9.6 mW
    VCCINT_PSFP         205.4 +-  0.4 mW       202.7 +- 0.3 mW
    VCC_DDR4                  --                31.8 +- 0.2 mW
  die temperature        +0.269 +- 0.031 C      +0.463 +- 0.034 C
  array temperature      +0.179 +- 0.031 C      +0.448 +- 0.033 C
  energy per event         25.35 uJ               16.59 uJ

The headline design draws 2.2x the power of the hybrid, and it is worth it:
per event it uses 1.53x LESS energy, 25.35 -> 16.59 uJ.

Where that comes from is the interesting part. Split the two rails that move:

  VCCINT, the compute rail, scales 3.385x against a throughput ratio of
  3.355x. The two agree to 1%, so the compute energy per event is constant:
  12.30 uJ before, 12.41 uJ after. Moving the embedding onto the array did
  not make the arithmetic cheaper. It removed a bottleneck, so the same
  per-event energy is delivered 3.36x faster.

  VCCINT_PSFP, the A72 host domain, is unchanged at ~205 mW (ratio 0.987).
  It is a fixed cost of running the host loop, not a per-event cost. Spread
  over 3.36x more events it falls from 11.90 to 3.50 uJ per event.

So the entire energy gain, 25.35 - 16.59 = 8.76 uJ, is the 8.40 uJ saved on
the host plus rounding. The accelerator itself costs the same per event
either way. That is the honest statement: the array did not make the
computation more efficient, it made the fixed overhead cheaper to amortise.

The DDR4 rail only becomes visible in the fast design, 31.8 mW, because it
is now moving events 3.36x faster.

Both temperature rises are small and well resolved, under half a degree at
a standard error of 0.034 C. The board is nowhere near a thermal limit; the
array rise, +0.448 C, is now almost equal to the die rise, +0.463 C, whereas
in the slower hybrid the array lagged the die (+0.179 against +0.269), which
is what you expect once the array is doing the embedding as well.

Two controls worth noting. The array temperature does not rise in the fabric
design, +0.071 C against a standard error of 0.032, the only entry in the
whole campaign that fails significance: the array really is idle there. And
the A72 domain draws the same 203 to 206 mW in all three designs, so it is a
fixed cost of running the host loop, not a per-event cost.

The honest reading: the array is NOT more efficient at the arithmetic
------------------------------------------------------------------
Compute-rail energy per event goes the WRONG way when work moves to the
array: 5.42 uJ in the fabric, 12.30 and 12.41 uJ in the two hybrids. Doing
this computation on the AI Engines costs about 2.3x more energy per event
than doing it in the fabric.

The hybrid still wins on total energy, 31.79 -> 16.59 uJ marginal and
1276 -> 257 uJ whole-board, but not because the array computes more cheaply.
It wins because it is 7.2x faster, and both fixed costs, the 205 mW host loop
and the ~10 to 14 W platform, are then spread over 7.2x more events.

This only holds if the throughput is used
-----------------------------------------
Every energy-per-event figure above assumes the design runs saturated, which
is the right assumption for a trigger but not a free one. Configuring the AI
Engine array costs 3.9 W of idle power on its own, 13.9 W against 10.0 W for
the fabric image, whether or not the array is doing anything. Run the hybrid
at the fabric's 8,056 ev/s and it would burn about 1729 uJ/event against the
fabric's 1276, i.e. worse. The array is worth its static cost only above
roughly 10,000 ev/s, and it pays 5x over at 57,917.

Cross-check against the 2026-08-27 campaign
-------------------------------------------
That 200-cycle run measured the older all-PL build (4,869 ev/s, float layer
norm) at dP = 255.2 +- 6.3 mW with VCCINT 46.8 +- 6.1 mW. This 49-cycle run
on the current fabric build gives 256.1 +- 9.9 and 43.7 +- 9.8 mW: the same
within errors, despite 1.65x the throughput, because the integer layer norm
does correspondingly less work per event. Per event the compute rail improved
9.61 -> 5.42 uJ. The agreement of the totals across two campaigns six weeks
apart is a useful check that the lock-in method is stable.


The old PL-vs-hybrid figure's shaded band understates the PL load
=================================================================
In figs/board_lockin_pl_vs_aie_120s.png the PL trace stays high for about
10 s past the shaded compute band and looks like it decays late. It does not.
Those two campaigns set the ON window by an ITERATION COUNT, so a slower
design ran a LONGER window:

  PL   pl_stream_batched2, 280 iterations  -> ON window 118.1 s
  AIE  aie_stream,         920 iterations  -> ON window 108.4 s

The band is drawn at the shorter of the two, 108.4 s, so the PL load really
was still running for another 9.7 s. Nothing is lagging; the shading simply
does not describe the orange trace.

This is the failure the time-based rewrite of the lock-in script was for. The
current campaigns hold their load for 122.1 s (fabric) and 124.1 s (hybrid
with the embedding on the array), 2 s apart instead of 10, and in
figs/board_lockin_current_designs.png both traces fall at the band edge.

What actually happens at the OFF edge, from the raw fold
-------------------------------------------------------
Two different things, and only one of them is physics.

Power is a step, not a decay. The A72 rail, which is 205 of the 256 mW, goes
0.367 -> 0.163 W across a single 1 Hz sample. Its apparent width comes from
the measurement, not the board: 1 Hz sampling, a 2 s polling grid for the
on_end stamp, and the plot's centred five-sample smoothing.

Temperature is a real decay, but a fast one: 81% of the 0.397 C fall is gone
within 1 s, and the remainder is a slow package tail at the noise floor. The
die is thermally small and tightly coupled to the logic that heats it.

Neither affects any number reported here. The folding skips 20 s after the
OFF edge, ten to twenty times the transition width, and the answer does not
depend on that choice: sweeping the skip from 5 s to 60 s moves the fabric
dP over 0.2558 to 0.2602 W, a 1.7% spread against a 3.9% standard error.

One caveat visible in the new figure: the hybrid's temperature is still
climbing at the end of the 120 s ON window, so its dT is a lower bound on the
steady state. Its power has plateaued, so dP is not affected.

300 s windows: power and temperature from ONE measurement
=========================================================
Both designs rerun at 300 s ON / 300 s OFF, 25 cycles, so power and
temperature come from the same campaign and the same windows rather than
being stitched from two. Window distribution identical on both designs:
{300 s: 11 cycles, 301 s: 14}.

                          fabric only          hybrid + embedding
  total dP          266.1 +- 14.9 mW        1004.7 +- 16.7 mW
    VCCINT           51.5 +- 14.1 mW         753.9 +- 15.7 mW
    VCCINT_PSFP     205.1 +-  0.3 mW         207.2 +-  0.3 mW
    VCC_DDR4          4.1 +-  0.1 mW          32.4 +-  0.1 mW
  die dT           +0.430 +- 0.050 C       +0.621 +- 0.067 C
  array dT         +0.130 +- 0.049 C       +0.602 +- 0.067 C
  energy per event     33.03 uJ                 17.35 uJ
    of which compute    6.39 uJ                 13.02 uJ
    of which host      25.46 uJ                  3.58 uJ

BOTH quantities were understated at 120 s, for the same reason
--------------------------------------------------------------
  hybrid dP   952.7 -> 1004.7 mW   +5.5%  (2.6 sigma)
  hybrid die   0.467 -> 0.621 C    +33%
  hybrid array 0.448 -> 0.602 C    +34%
  fabric dP   253.9 ->  266.1 mW   +4.8%  (0.6 sigma, not significant)
  fabric die   0.368 ->  0.430 C   +17%

The temperature was expected: at tau = 56 to 71 s a 120 s window reaches only
about 85% of the steady-state rise. The POWER shift was not, and the reason
is the same window. Power itself is a step, settled within about 2 s, but the
baseline it is measured against is not: a 120 s OFF window leaves the die
warm, warm silicon leaks more current, so the OFF power sits high and dP comes
out small. Both quantities need a long OFF window, not just a long ON window.
The earlier prediction that dP would be insensitive to window length was
wrong for this reason.

The fitted asymptotes from the 120 s data (0.642 and 0.636 C) match the
measured 300 s values (0.621 and 0.602) to 3 to 5%, so the exponential fit
was sound even though the percentage arithmetic built on it was not.

What does not change
--------------------
Energy per event 33.03 -> 17.35 uJ, a factor 1.90, against 1.92 at 120 s. The
hybrid still costs about twice the COMPUTE energy per event, 13.02 against
6.39 uJ, and still wins only by amortising fixed cost over 7.2x the
throughput. The A72 rail reads 205.1 and 207.2 mW across two designs that
differ sevenfold in rate, which is the cleanest form of the fixed-host-cost
claim in this work.

One control weakens
-------------------
The fabric's AIE array rise is no longer cleanly null: +0.065 +- 0.040 C at
120 s (1.6 sigma) becomes +0.130 +- 0.049 C at 300 s (2.7 sigma). Over 300 s
heat conducts from the die, which sits at +0.430 C. So "the array is idle in
the fabric design" should rest on the power rail, VCCINT +51.5 mW against
+753.9 mW, rather than on a null temperature.
